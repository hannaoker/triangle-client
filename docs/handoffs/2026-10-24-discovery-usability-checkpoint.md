## What the source change does (items 5 and part of 3)

- **Titles.** Each lifecycle hook reads its own session's title: Claude from `~/.claude/sessions/<pid>.json` (`name`), found by walking up to the ancestor `claude` process and accepting only a record whose `sessionId` matches and whose `procStart` equals that process's `ps` start time (UTC); Codex from `threads.name`, else `threads.title`, in `state_5.sqlite` (same read-only point lookup as origin; columns optional). Titles are sanitized (one line, 80 chars, control/bidi characters removed, 28+ char token-like runs masked) at hook, broker and view. Label becomes `Claude · <title> · <workspace> · <hash8>`; a `title` field is added. Owner switch: `setup-discovery --no-titles` (`config.discovery.titles:false`, kept on reruns, `--titles` restores). Titles are shown to every configured directory reader.
- **Presence.** Hooks also record the host process (pid, exact start, scope `session` or `shared`; Codex Desktop hooks run under the shared `codex ... app-server`, so scope `shared`). The supervisor probes liveness with one `ps -axo pid=,lstart=` per refresh (5 s cache). Rows now carry `presenceEvidence {kind: end-event | mcp-lease | host-process | host-process-gone | none, scope?, observedAt?}`. `online` needs a live lease or a live per-session host; a shared host alive is `unknown`; a vanished or reused pid is `offline`; a probe failure is `unknown`, never `offline`. Pids are never returned to readers.
- **Attachment hint (item 3).** Claude rows gain `attachment: attached | not-attached | ended` and an `attachmentHint` saying the chat must be reloaded/restarted so its MCP server loads. A session with no lease is no longer reported `offline`.
- Journal: four nullable columns added additively (`title`, `host_pid`, `host_start`, `host_scope`); a pre-title journal migrates and keeps handles. MCP `triangle_list_sessions` descriptions updated in both adapters.

Gotcha fixed on the way: on macOS `ps -p a,b` prints **nothing** if any listed pid is gone, which made every live session look dead; the probe reads the whole table instead.
