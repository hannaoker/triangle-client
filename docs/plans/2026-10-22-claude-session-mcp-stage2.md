# Claude Session MCP Adapter — Stage 2 Implementation Plan

## 1. Architecture and State Ownership

- **Supervisor (Broker & Journal)**:
  - Exclusively owns SQLite (`local-messaging-journal.mjs`), migrations, and file locks.
  - Owns client enrollment, identity ACLs, and interactive grant validation (`local-messaging-interactive-session.mjs`).
  - Distinct Claude wake binding initialized by supervisor lifecycle from validated interactive integration (`claude-integration.json`). Never uses peer-supplied target/thread, and strictly avoids Codex target reuse. Initialization/rebind generation matches authorized interactive tuple (`current.generation`, `current.bindingId`).
  - Owns wake state machine transitions in `local_wake_bindings` (`idle`, `submitting`, `accepted_awaiting_ack`, `uncertain`, `stale_held`).
  - Evaluates obligations and maintains server-owned backlog fingerprints (clientFingerprint has no authority).
  - Handles authenticated RPCs (`reserve_wake_notification`, `report_wake_result`, `ack_notification`) with full generation/session/binding fencing.
  - Never accesses Claude socket paths or tokens.
- **Claude MCP Child Process (`claude-session-mcp-child.mjs`)**:
  - Standalone MCP child running on stdio for Claude session integration. Generic `local-messaging-mcp-adapter.mjs` remains pure tool mapping.
  - Inherits `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_SOCKET`, and `CLAUDE_CODE_MESSAGING_TOKEN` from process environment.
  - Strictly owns inherited socket token; never writes it to disk, SQLite, logs, stdout/stderr, or forwards it over RPC.
  - Opens no SQLite connections, runs no extra daemons, and performs no token-file or registry discovery.
  - Connects to supervisor control socket, exchanges owner-paired credentials for scoped turn grants, and exposes Claude-only stdio MCP tools (`triangle_list_inbox`, `triangle_claim_message`, `triangle_reply_message`, `triangle_ack_notification`, `triangle_send_message`, `triangle_get_status`). Ordinary Codex MCP tool surface remains unchanged.
  - Missing/mismatched inherited session UUID fails closed immediately.
  - Missing or malformed socket support is detected before reservation and degrades cleanly to pull-only if session identity still matches. Unsupported explicit version fails push.
  - Executes wake delivery to inherited socket via delivery primitive and reports results to supervisor.
  - Manages wake scheduling loop with min interval, token refresh, and clean shutdown closing sockets/timers without clearing outstanding uncertainty. Never automatically replays mutating calls after transport/auth failure.

## 2. Obligation Tracking and Codex Invariants

- **`getWakeObligations(targetIdentity)` Extension**:
  - Current obligations: unread replies (`local_replies WHERE recipient = ? AND consumed = 0`) and sender-held work (`local_messages WHERE sender = ? AND phase = 'held'`).
  - Stage 2 addition: inbound queued interactive requests (`local_messages WHERE recipient = ? AND phase = 'queued_local' AND recipient_type = 'interactive'`) are queried only when `targetIdentity` is an interactive target.
  - Preserves Codex semantics: runner targets ignore interactive queues; runner dispatch tests pass unchanged.
  - `snapshotFingerprint` computes SHA-256 over sorted reply IDs/timestamps, held IDs/timestamps/late flags, and queued interactive IDs/timestamps. Canonical state and fingerprint authority are server-owned. Backlog is unchanged if fingerprint equals `last_acknowledged_fingerprint`.
  - Notification hints contain only fixed infra metadata (counts, fixed template, late flags). No reply body, token, raw socket path, or stack trace in hints, logs, stdout, or stderr.

## 3. Authenticated Broker RPCs and Fencing

All interactive RPCs require signed bearer turn credentials carrying `{ senderId, sessionId, generation, bindingId, senderType: 'interactive' }`.

1. **`reserve_wake_notification`**:
   - **Parameters**: `{ reservationId: string, clientFingerprint?: string }`
   - Stable `reservationId` must be generated by child before first RPC.
   - **Atomic Reservation**:
     Performs atomic reservation in `local-messaging-journal.mjs`:
     ```sql
     UPDATE local_wake_bindings
     SET delivery_state = 'submitting',
         active_wake_id = ?,
         active_fingerprint = ?,
         last_submitted_at = ?,
         updated_at = ?
     WHERE target_identity = ?
       AND generation = ?
       AND binding_id = ?
       AND delivery_state = 'idle';
     ```
   - **Permission Semantics**:
     - ONLY a newly won atomic reservation returns `deliveryAllowed: true` and `reserved: true`.
     - An exact duplicate retry (same `reservationId`) returns prior metadata with `deliveryAllowed: false` and `reserved: false` (with `isDuplicate: true`). No child interprets a retry as permission to write again.
     - Competing children or non-idle states return `{ reserved: false, deliveryAllowed: false, state: delivery_state }`.
     - Two concurrent children or retries yield exactly one delivery permit. Ambiguous RPC outcome => no delivery retry.
     - Enforces min interval (`now - last_submitted_at >= 15000`) and unacknowledged obligations.

2. **`report_wake_result`**:
   - **Parameters**: `{ wakeId: string, generation: number, sessionId: string, bindingId: string, result: 'accepted' | 'uncertain' | 'failed' }`
   - **Fencing**: Conditions on full `target_identity`, `sessionId`, `generation`, `binding_id`, AND active wake (`active_wake_id === wakeId`).
   - **No failed -> idle**:
     - All failed and ambiguous delivery attempts (`failed` or `uncertain`) retain a non-idle `uncertain` state. Pre-write connect failures or post-write timeouts do NOT reset to `idle`.
     - `'accepted'`: Transitions `submitting` -> `accepted_awaiting_ack`. Represents socket write acceptance only, not model turn execution or acknowledgment.
     - `'uncertain' | 'failed'`: Transitions `submitting` -> `uncertain`. NO AUTOMATIC RESEND.
   - **Early Ack & Rebind Races**:
     - If wake was already acknowledged (`last_acknowledged_wake_id === wakeId` and binding is `idle`) or rebound, a late report NEVER resurrects an acknowledged or rebound wake. Harmless no-op return.
     - Stale generation or binding mismatch throws `stale_wake_generation` or `binding_changed`.

3. **`ack_notification`**:
   - **Parameters**: `{ wakeId: string, generation: number }`
   - Server routes interactive callers (`claims.senderType === 'interactive'`) to interactive wake acknowledgment, preserving Codex notifier routing for desktop callers.
   - **Multi-State Ack**:
     - Handles `accepted_awaiting_ack`, `submitting`, and `uncertain` (wake can reach Claude before child's report RPC arrives).
     - Transitions state to `idle`, updates `last_acknowledged_wake_id = wakeId`, `last_acknowledged_fingerprint = active_fingerprint`, clears `active_wake_id` and `active_fingerprint`.
     - Preserves `stale_held` rejection: bindings in `stale_held` or with generation/binding mismatch fail closed.

4. **Crash Recovery & Rebind Fencing**:
   - Supervisor crash recovery on startup resets `submitting` wake bindings to `uncertain`.
   - Supervisor integration rebind bumps generation and transitions non-idle bindings to `stale_held`. Stale child reports and acks fail closed.

## 4. MCP Tools & Child Execution Surface

- **Child Entry Point**:
  - Explicit CLI command: `packages/agent-worker/src/local-messaging-cli.mjs` supports `claude-session-mcp --config <path> [--integration <path>] [--expected-version <ver>]`. Tested directly from source.
  - Requires explicit expected Claude version from config/argument and verifies against inherited environment.
  - Requires inherited session UUID (`CLAUDE_CODE_SESSION_ID`) matching owner integration pairing. Missing or mismatched UUID fails closed immediately.
  - Installed wrapper remains unchanged until separate bundle/release gate. No automatic activation during this task.
- **MCP Tool Surface in `claude-session-mcp-child.mjs`**:
  - Interactive tools: `triangle_list_inbox`, `triangle_claim_message`, `triangle_reply_message`, `triangle_ack_notification`, `triangle_send_message`, `triangle_get_status`.
  - Ordinary Codex MCP tool surface in `local-messaging-mcp-adapter.mjs` remains unchanged.
  - Message bodies remain free-form text or JSON.
  - Scoped Triangle turn credentials refreshed automatically via `exchange_session`, but NEVER automatically replay mutating calls after transport/auth failure.
  - Redaction hygiene: Sentinel socket tokens, raw socket paths, and stack traces never appear in tool lists, RPCs, logs, stdout, or stderr.
